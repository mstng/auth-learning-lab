# ADR 003: 実行後のイベント再生
採用。HTTPを13回に分けてサーバー処理を不自然に停止する方式を避け、通常のログイン・Profile APIを実行し、その実行記録を再生する。ブラウザーのCookie保存はサーバーだけでは断定できないため、保存指示として説明し、次のProfileリクエストのCookie受信で確認する。

DBは各イベントに紐づくスナップショットを持ち、画面の現在状態と明確に区別する。Browserの資格情報入力とAPI呼び出し開始は説明用イベント、サーバー側SQL・ハッシュ照合・Session生成は実行イベントと表示する。

一般的なHTTP bodyの認証結果と、教材のtrace/stateメタデータを切替表示。パスワード平文をログ・レスポンスに含めない。学習空間IDは表示ログで伏せる。Session IDとPassword Hashを返す観察APIはLAB_MODE=true専用で、製品認証APIとして利用しない。
